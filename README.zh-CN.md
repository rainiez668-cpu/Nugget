# Nugget

[English](README.md) | 简体中文

**从杂乱的 Brief 中，发现真正值得投入的设计机会。**

Nugget 是一款面向学生和独立设计师的全球设计竞赛发现与 AI 辅助提案工具。

它帮助设计师发现值得参与的竞赛机会，判断一场比赛是否值得参加，解读复杂的竞赛 Brief，并将参赛要求转化为结构化的设计方向与可用于提交的提案材料。

Nugget 并不把 AI 当作“一键生成创意”的工具，而是强调：**先确认参赛资格、规则、交付要求和信息来源可信度，再进入生成阶段**。

---

## 项目概述

设计竞赛分散在不同的网站、国家、语言和设计领域中。参赛资格、报名费用、截止日期、交付要求和评审标准等关键信息，往往隐藏在冗长的竞赛页面或 Brief 中。

对于学生和独立设计师而言，难点不仅是找到比赛，还需要判断：

- 这场比赛适合我吗？
- 我符合参赛资格吗？
- 是否需要支付报名费？
- 到底需要提交哪些内容？
- 评审更看重什么？
- 如何把 Brief 转化为可执行的设计方向？

Nugget 将这些决策整合进一套连续的工作流：

**Discover → Qualify → Analyze → Create → Review → Submit**

---

## 核心工作流

### 1. Discover｜发现竞赛

通过全球设计竞赛雷达，浏览不同设计领域、国家和竞赛类型的机会。

支持通过以下条件搜索和筛选：

- 设计领域
- 报名费用
- 参赛资格
- 竞赛类型
- 奖项
- 截止日期

系统优先推荐免费参赛的竞赛机会，让学生和独立设计师能够更高效地发现值得参与的项目。

### 2. Qualify｜资格判断

在开始生成创意之前，Nugget 会先呈现决定一场比赛是否值得投入的实际条件。

竞赛详情包括：

- 参赛资格
- 报名费用
- 奖项
- 截止日期
- 信息来源可信度
- 官方来源依据

### 3. Analyze｜解读 Brief

用户可以直接将 Discover 中发现的竞赛 Brief 发送至 Studio。

Nugget 会将 Brief 结构化整理为：

- 核心要求
- 交付内容
- 格式限制
- 评审倾向
- 潜在机会
- 风险与注意事项

### 4. Create｜生成设计方向

Studio 不会只返回一个泛化的 AI 答案，而是生成三个结构化的概念方向。

每个方向可包含：

- 概念策略
- 空间或产品设计思路
- 视觉氛围
- 与评审标准的关联
- 图像生成 Prompt
- 概念说明
- 展板版式规划
- 提交检查清单

### 5. Review｜人工审核

在进入下一阶段之前，完整参赛工作流会让重要决策保持清晰可见。

设计概念、视觉素材、版式和提交材料都被视为需要人工审核的阶段性成果，而不是自动接受 AI 生成的结果。

### 6. Submit｜准备提交

工作流可以将提案材料整理为结构化的参赛材料包，并生成模拟提交回执，同时提供前往竞赛官方来源的入口。

当前公开原型不会自动向第三方竞赛平台提交作品。

## 产品原则

### 免费参赛优先

竞赛发现优先推荐参与门槛较低的机会，尤其关注学生和独立设计师的实际需求。

### 先确认信息，再开始生成

在 AI 辅助创意开始之前，先呈现信息来源、参赛资格、截止日期和竞赛要求。

### 先理解规则，再使用 AI

Nugget 将 Brief 看作一组需要理解的设计约束，而不仅仅是一段可以直接用于生成的 Prompt。

### 先建立结构，再进行自动化

复杂的参赛任务会被拆分为清晰可见的阶段，让用户理解系统正在做什么，并在必要时进行干预。

### AI 提议，人来决定

AI 生成的概念方向和视觉素材都被视为候选方案。重要的设计决策始终由设计师审核和决定。

## AI 架构

Nugget 采用基于 Provider 的 AI 架构，目前支持三种模式：

- `mock`
- `openai`
- `anthropic`

Mock 模式是默认体验，无需 API Key。

配置受支持的 Provider 后，服务端 API Routes 可以调用 OpenAI 或 Anthropic 完成 AI 辅助分析。如果配置了有效的 API Key，视觉生成工作流还可以调用 OpenAI Images API。

API Key 仅由服务端读取，不会暴露至浏览器端。

如果未配置相应的 Provider 凭证，Nugget 会自动回退至内置的 Mock 模式。

---

## Mock AI

Mock 系统并不是简单的占位功能，而是一套完整的演示模式。

它能够识别输入 Brief 中的基础信息，例如比赛名称、截止日期、报名费用和设计领域，并返回结构化的竞赛分析以及三个概念方向。

因此，即使不连接任何外部 AI 服务或产生 API 成本，也可以完整测试 Nugget 的主要产品流程。

## 竞赛数据

目前的竞赛雷达使用一套经过整理的演示数据集，主要用于测试和展示产品体验。

当前版本**不代表已经实现全网设计竞赛的实时、完整收录**。

如果进一步发展为正式产品，竞赛发现系统还需要：

- 定时数据采集
- 持久化竞赛数据存储
- 多语言搜索
- 针对不同信息来源的数据解析
- 重复数据去重
- 截止日期定期复核
- 信息来源定期复核

这种区分是有意为之：当前原型的重点是验证产品工作流，而不是将演示数据包装成实时竞赛数据。

## 本地优先的项目存储

Studio 项目存储在浏览器 `localStorage` 中。

用户可以：

- 保存分析结果
- 重新打开历史项目
- 删除项目
- 将项目导出为 Markdown
- 将完整的结构化项目数据导出为 JSON

当前原型无需注册账号。

项目暂不支持跨浏览器或跨设备同步。

## 环境变量

如果希望使用外部 AI Provider，请创建本地 `.env.local` 文件：

```env
AI_PROVIDER=mock
OPENAI_API_KEY=
ANTHROPIC_API_KEY=
```

`AI_PROVIDER` 支持：

```text
mock
openai
anthropic
```

如果缺少对应 Provider 的凭证，系统会自动回退至 Mock 模式。

请勿将 `.env.local` 或 API Key 提交至代码仓库。

如果没有配置 OpenAI 图像生成所需的 API Key，完整参赛工作流会使用内置设计样例。

## Demo 流程

一个典型的 Nugget 使用流程如下：

1. 打开 **Discover**。
2. 搜索或筛选可参与的竞赛。
3. 打开竞赛详情，查看参赛资格、报名费用、奖项、截止日期和信息来源。
4. 将竞赛 Brief 发送至 **Studio**。
5. 查看竞赛要求、评审倾向、风险和潜在机会。
6. 探索三个概念方向。
7. 保存项目，或导出为 Markdown / JSON。
8. 对符合条件的竞赛，继续进入完整参赛工作流。
9. 检查交付要求并确认概念方向。
10. 生成或加载视觉素材。
11. 组合提案展板。
12. 在模拟最终提交前审核完整的参赛材料包。

## 项目范围

Nugget 目前是一个可运行的功能型产品原型。

- 竞赛发现与筛选
